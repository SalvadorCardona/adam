# Steam Input : la disposition conseillée

Dans Steam, page du jeu → icône manette → *Disposition du contrôleur* →
*Modèles* → **« Gamepad »**.

Le jeu lit la manette par la Gamepad API au mapping « standard ». Le modèle
« Gamepad » présente le Steam Deck comme une manette Xbox : chaque bouton
arrive au jeu sous son indice standard, et le jeu affiche A, B, X, Y.

| Deck | Jeu |
| --- | --- |
| Stick gauche | marcher |
| Stick droit | curseur du jeu |
| A | cliquer (tenu : glisser) |
| B | retour, fermer |
| X | « Bâtir » |
| Y | le sac |
| Croix | passer d'un bouton à l'autre |
| L1 / R1 | zoom par crans |
| L2 / R2 | zoom continu |
| R3 | revenir sur Adam |
| Menu (☰) | pause — puis « Quitter » |
| Vue (⧉) | carte du monde |

À éviter : le modèle « Web browser » (les sticks deviennent souris et molette,
le jeu ne voit plus de manette) et « Gamepad with mouse trackpad » si le pavé
droit gêne : le curseur du jeu suit le stick droit, pas la souris.

Les pavés tactiles et les boutons arrière (L4, L5, R4, R5) ne servent à rien
dans le jeu : on peut y poser ce qu'on veut. L'écran tactile marche aussi
(joystick et taps, comme sur un téléphone).

Pas de fichier `.vdf` ici : une configuration Steam Input écrite à la main ne
se vérifie que sur un Deck, et le modèle « Gamepad » fait déjà exactement ce
qu'il faut. Une configuration exportée d'un Deck pourra la rejoindre.
